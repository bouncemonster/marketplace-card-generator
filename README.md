# Marketplace Card Generator

**RU** — Генератор карточек товаров в стиле маркетплейсов (WB/Ozon) для **любого** магазина:
LLM-арт-директор придумывает продающий контент на каждый товар, image-модель рендерит его
дословно, VLM-QA не пропускает брак, а точечный edit-repair чинит битый текст без полной
перегенерации. Один файл, только stdlib, весь стиль магазина — в JSON-профиле.

**EN** — AI pipeline that turns plain product photos into marketplace-style infographic
cards (WB/Ozon look) for any store: per-product art-director brief → verbatim image
generation → VLM QA gate → targeted text repair. Single-file Python, stdlib only,
store design lives in a JSON profile. ~$0.02/card with Seedream 5.0 Flash.

## Что получается

Карточка 1:1 (2K): три яруса типографики (тип товара → гигантский цветной заголовок →
подзаголовок), товар с фирменным наездом на заголовок, плашки выгод с линейными иконками,
чёрный бейдж с цифрами, нижняя строка тегов. Все тексты — **дословно из брифа**, который
сочинил LLM-арт-директор по фото и описанию товара (никаких «высокое качество» — только
конкретика из характеристик).

## Быстрый старт

```powershell
# 1. Настройте магазин: скопируйте пример и поправьте палитру/дизайн-систему/модели
copy profile.example.json profile.json

# 2. Подготовьте products.csv: id,title,description,category,image (путь к фото)
#    и сами фото в папке photos/

# 3. Пайплайн (каждый шаг resume-safe: повторный запуск не переплачивает)
$env:OPENROUTER_API_KEY='...'
python cardgen.py scan    --products products.csv
python cardgen.py brief   --max-cost-usd 1.0     # ~$0.002/товар
python cardgen.py build
python cardgen.py send    --max-cost-usd 8.0     # $0.018/карточка (Flash)
python cardgen.py qa                             # ~$0.0015/карточка
python cardgen.py fix     --max-cost-usd 3.0     # починка hard-fail
python cardgen.py qa                             # допроверка _fx/_r
python cardgen.py cost                           # сводка затрат
```

Результаты: `out/cards/*.jpg` (карточки), `out/review_sheet.html` (контактный лист ручной
приёмки), JSONL-журналы `out/{manifest,briefs,requests,results,qa}`.

## Этапы

| Этап | Что делает | Модель | Цена/товар |
|---|---|---|---|
| `scan` | проверка CSV и фото, форма кадра → manifest.json | — | $0 |
| `brief` | арт-директор: заголовок, выгоды, плашки, шрифты | gemini-3-flash (настраив.) | ~$0.002 |
| `build` | сборка image-запросов (компактный режим для Seedream) | — | $0 |
| `send` | генерация карточек с бюджетным потолком | seedream-5-0-flash (настраив.) | $0.018 |
| `qa` | детерминированные проверки + VLM-рубрика + контактный лист | qwen omni (настраив.) | ~$0.0015 |
| `fix` | edit-починка битого текста ИЛИ перегенерация с адресной подсказкой | image-модель | $0.018 |

## Ключевые решения (выношены из боёв)

1. **Тексты придумывает LLM, а не image-модель.** Image-модель обязана рендерить бриф
   символ-в-символ; QA проверяет следование ему. Иначе — выдуманные характеристики и цены.
2. **Бюджет текста.** Модели надёжно рендерят только короткие фразы (3–6 слов). Валидатор
   брифа отвергает длинные строки с авто-перевызовом — это убивает 90% глиблицы.
3. **Компактный промпт для Seedream 5.0 Flash.** Простыня ТЗ на ~3.6k токенов разбивает
   Flash на орфографии; короткий фокусный промпт (дизайн-система + все тексты в кавычках
   одной строкой) даёт чистый текст. Для NB2/gpt-image-2 остаётся полный режим.
4. **QA-политика по движку.** Приёмы, которые движок физически не делает (у Flash это
   «товар поверх заголовка»), понижаются из hard в soft — иначе бесконечный цикл
   перегенераций недосягаемого.
5. **Точечная починка вместо лотереи.** Если товар и вёрстка хороши, а бит только текст —
   edit-проход по готовой карточке («перерисуй только надписи, сохрани всё остальное»),
   $0.018 вместо перегенерации всей композиции.

## Зависимости

Только стандартная библиотека Python 3.9+. Pillow опционален (сжатие фото под base64,
детерминированные проверки QA; без него всё работает, кроме этих удобств).

## Секреты и безопасность

Ключ OpenRouter берётся только из переменной окружения `OPENROUTER_API_KEY`.
Никогда не коммитьте ключи; `out/` и `profile.json` (может содержать внутренние данные)
в `.gitignore`.
